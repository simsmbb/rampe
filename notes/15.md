# In Simple Terms

Temporal is:

```text id="m1n2o3"
a fault-tolerant workflow engine
```

that lets you reliably run:

* long-running processes
* distributed tasks
* retries
* approvals
* orchestrations
* AI workflows

without manually managing:

* queues
* cron jobs
* retry logic
* workflow state
* resumability

---

# The Easiest Way To Understand Temporal

Imagine this workflow:

```text id="p4q5r6"
1. User uploads claim
2. AI analyzes document
3. Wait for human approval
4. Send payment
5. Notify customer
```

Now imagine:

* server crashes at step 3
* deployment occurs
* Kubernetes restarts pod
* network fails

Without Temporal:
you must manually handle:

* saving workflow state
* retries
* restoring execution
* timers
* approvals
* partial progress

This becomes extremely difficult.

---

# Temporal Handles This Automatically

Temporal stores:

* workflow state
* execution history
* retries
* timers
* checkpoints

So workflows resume safely even after failures.

---

# It Is VERY Different From Normal Backend Code

Normal backend:

```python id="s7t8u9"
process_claim()
```

runs in:

* memory
* one process

If process dies:

* execution dies.

---

# Temporal Workflow

```python id="v0w1x2"
@workflow.defn
class ClaimWorkflow:
    @workflow.run
    async def run(self):
        ...
```

Temporal persists:

* every step
* every state transition

into durable storage.

So execution survives crashes.
